# Магазин игр (Store)

Реализовано. Позволяет искать и устанавливать ROM'ы прямо из лаунчера, без ручного скачивания файлов. Источник — тот же раздел NES/Dendy на [emu-land.net](https://www.emu-land.net/consoles/dendy/roms), что уже используется для метаданных (`src-tauri/src/metadata/scraper.rs`, `NES_SECTION_ID`) — переиспользует оттуда `BASE_URL`/`NES_SECTION_ID`/`build_client` (сделаны `pub(crate)`).

UI-поведение описано здесь на уровне поведения; экран как таковой — см. `Store Screen` в [screens.md](screens.md). Реализация: `src-tauri/src/store/scraper.rs` (HTTP/парсинг), `src-tauri/src/commands/store.rs` (Tauri-команды: `store_search`, `store_browse`, `store_list_files`, `store_install`), `src/screens/StoreScreen/`.

## Как находим игру на сайте

Раздел ROM'ов **на самом деле имеет полнотекстовый поиск** — тот же эндпоинт `/search_games?id=13&q=...`, что уже используется в `metadata/scraper.rs` для поиска одной игры по названию, здесь просто отдаёт **все** совпадения, а не только первое. Изначальное предположение («сайт не имеет поиска») было ошибочным — исправлено после проверки вживую.

- **Поиск** (непустой запрос): `GET /search_games?id=13&q=<query>` → каждый результат — `<p>` внутри `.fllinks`: `<a href="/consoles/dendy/roms/<slug>">Title</a>` плюс превью-картинка (`<img class="preview" src="//ss.emu-land.net/...">`, протокол-относительный URL) и теги жанра/игроков (теги пока не используются). Картинка — `image_url` в `StoreGameSummary`, см. «Превью-картинки» ниже.
- **Просмотр по буквам** (пустой запрос — фолбэк/ручное листание): `GET /consoles/dendy/roms/<letter>` (первая страница) или `/consoles/dendy/roms/<letter>/<page>` (page > 1). `<letter>` — одна из `BROWSE_LETTERS` (`0-9`, `a`..`z`, реальный список вкладок навигации сайта, зашит и на бэкенде как белый список, и на фронтенде для рендера вкладок). Каждая игра — блок `.fcontainer`, заголовок/ссылка — `.rheader a`, превью-картинка — `.picture img` (тот же `src`, протокол-относительный). Общее число страниц — из `.num a[title="Последняя"]` (сайт сам явно даёт номер последней страницы в ссылке «»» — не нужно перебирать страницы вслепую до пустой, как предполагалось раньше).
- И поиск, и просмотр по буквам возвращают `slug` + `title` + `image_url` (последний — не всегда: `Option`, если игра почему-то без превью на сайте) — числовой id игры (нужен для скачивания) на этих страницах **не публикуется**, только на странице самой игры.
- **Список файлов игры**: сначала `GET /consoles/dendy/roms/<slug>` (страница игры) — числовой id зашит в JS-обработчике первой кнопки скачивания (`onclick="mgame('...act=getmfl&id=24602', ...)"`, парсится как подстрока, без явного CSS-селектора на `onclick`, чтобы не зависеть от точной поддержки атрибутных селекторов). Берётся id из **первого** найденного вхождения на странице — ROM-хаки игры (если есть) идут в разметке ниже и создают собственные `id`, но всегда после основной игры. Затем `GET /consoles/dendy/roms?act=getmfl&id=<id>` возвращает файлы, сгруппированные по разделам сайта (`.collaps-item`, заголовок раздела — `.title span`): «Основные», «Переведённые», «GoodNES» и т.д. Каждый файл — `.item .file > a` (текст — имя файла, `href` содержит `fid`) + опционально `.size` (человекочитаемый размер).
- **Скачивание**: `GET /consoles/dendy/roms?act=getmfl&id=<id>&fid=<fid>` — 302-редирект на `dl.emu-land.net`, `reqwest` следует за ним автоматически (никакого специального `Referer` не требуется, в отличие от хотлинков обложек в `metadata/scraper.rs`).

Только `.zip`: часть записей на сайте (в основном раздел «GoodNES») — это `.7z`-архивы с целыми наборами ромов, а не одна игра; такие записи фильтруются на бэкенде ещё на этапе списка файлов (`list_files`) и до UI не доходят.

## Превью-картинки карточек

`ss.emu-land.net` (хост превью/скриншотов) блокирует хотлинки по Referer — тот же хост и то же ограничение, что у обложек метаданных (`metadata/scraper.rs::download_image`), поэтому `image_url` из поиска/просмотра по буквам напрямую в `<img src>` не отдаётся: 403.

Решение — по образцу обложек метаданных, но с отдельным кэшем и по требованию, а не пачкой:
- `commands::store::store_cover_image(slug, url)` скачивает картинку и кладёт в `<app-data>/store_previews/<slug>.<ext>` (уже скачанный файл не перекачивается повторно — проверка по существованию на диске). Отдельная от `<app-data>/covers/<game_id>.<ext>` директория и ключ, т.к. на момент просмотра магазина игра ещё не в библиотеке — `game_id` попросту нет.
- `app.security.assetProtocol.scope` в `tauri.conf.json` должен включать `$APPDATA/store_previews/*` (отдельной записью от `$APPDATA/covers/*`) — без неё `convertFileSrc` на путь из этой директории отдаёт заблокированный (не подгружающийся) `asset:` URL, а не 403 от самого сайта.
- Фронтенд (`StoreScreen`, компонент `StoreGameTile`) вызывает `store_cover_image` лениво по каждой отрендеренной карточке (не блокируя список запросом на ~20+ картинок разом при каждом поиске/смене буквы/страницы) — пока не резолвится, на месте обложки остаётся иконка-заглушка (та же, что раньше показывалась всегда).

## UI-поведение

- **Точка входа**: кнопка «Магазин» в шапке `Main Screen` (рядом с иконкой настроек) → переход на `Store Screen`.
- **Поиск**: строка поиска сверху, с дебаунсом (400мс), чтобы не бить в бэкенд на каждое нажатие клавиши. Непустой запрос — список результатов поиска (без пагинации, весь результат одним запросом — на практике сайт не отдаёт по конкретному названию сотни совпадений). Пустая строка — алфавитные вкладки (`0-9`, `A`..`Z`) + пагинация («← Назад» / «Страница N из M» / «Далее →»); смена буквы сбрасывает текущую страницу на 1.
- **Выбор версии**: клик по игре в списке (и в поиске, и при просмотре по буквам) открывает модалку со списком файлов этой игры (полученным через `store_list_files`) — раздел сайта показан подписью у строки, отдельного шага выбора категории нет.
- **Игра уже установлена**: если название карточки совпадает (без учёта регистра) с title уже установленной игры — единственный доступный способ сверки, у установленных игр нет сохранённого slug emu-land.net (см. [data-model.md](data-model.md)) — вместо списка файлов сразу показывается модалка «Игра уже установлена: сменить версию?». «Нет» просто закрывает модалку. «Сменить версию» открывает тот же список файлов, что и обычная установка (заголовок и кнопки подписаны «Заменить», не «Установить»), но по выбору файла происходит не новая установка, а **замена** — см. ниже.
- **Установка**:
  1. Клик «Установить» на конкретном файле.
  2. Если в `Settings.rom_library_paths` настроено **больше одного** пути — модалка выбора, в какую из папок установить (запрашивается заранее через `getRomLibraryPaths` при открытии экрана, чтобы не задерживать выбор запросом). Если путь один или список пуст — путь берётся автоматически (та же дефолтная `<app-data>/roms`, что и у сканирования), без вопроса.
  3. Бэкенд (`store_install`) заново резолвит числовой id по `slug` (список файлов и клик «Установить» — разные по времени действия пользователя, так что id не тащится через фронтенд), скачивает `.zip`, распаковывает из архива **первый** файл с расширением `.nes` (остальные файлы в архиве игнорируются).
  4. Имя файла на диске и название в библиотеке — **не** из архива (там часто регион/язык/ревизия в имени, например «Contra (Japan) (En) (Rev 1).nes»), а каноническое название игры с карточки магазина (`StoreGameSummary.title`, передаётся с фронтенда вместе с `slug`/`fid`) — то же самое название, что уже есть в базе emu-land.net. Название очищается от недопустимых в имени файла символов (`sanitize_filename`) и используется как есть для поля `title` в БД. При совпадении имени файла с уже существующим на диске добавляется суффикс `(2)`, `(3)`, ... — без перезаписи (актуально, если ставить несколько версий/регионов одной игры).
  5. Установленный `.nes` регистрируется в библиотеке так же, как при ручном добавлении файла (`insert_game_if_missing`, см. `src-tauri/src/commands/library.rs`).
  6. **Метаданные подтягиваются автоматически**, сразу после установки, без отдельного нажатия «Обновить» на вкладке «Метаданные»: `store_install` уже знает `slug` игры (использовался для скачивания), поэтому строит `game_page_url(slug)` и парсит описание/обложку/режим игры прямо с неё (`fetch_metadata_by_url`, переиспользует ту же логику парсинга страницы, что `fetch_metadata` для метаданных — просто без повторного поиска по названию, т.к. страница уже точно известна) — надёжнее, чем поиск по названию из `update_metadata`, и не зависит от эвристики точного совпадения в `find_game_url`. Best-effort: если сеть или разметка сайта подведут, установка всё равно завершается успешно, просто без описания/обложки — их можно дозагрузить вручную позже той же кнопкой «Обновить».
  7. Инлайновое сообщение об успехе на экране; принудительного перехода обратно в библиотеку нет — пользователь может продолжить ставить игры и уйти на `Main Screen` кнопкой «← Библиотека», когда захочет (список библиотеки там подтягивается заново при каждом заходе на экран).

**Замена версии** (после «Игра уже установлена» → «Сменить версию» выше) идёт почти тем же путём, с отличиями в `store_install` (параметр `replace_game_id`, `commands/store.rs::replace_installed_game`):
- Шаг 2 (выбор папки) пропускается — новый файл встаёт в ту же папку, что и старый (директория берётся из текущего `rom_path` игры), `target_dir` от фронтенда игнорируется.
- Старый файл удаляется с диска перед записью нового — поэтому шаг 4 (суффикс `(2)`, `(3)`...) в обычном случае не срабатывает: canonical-имя уже свободно, новый файл на диске просто занимает место старого. Если старый файл кем-то уже был удалён вручную — не ошибка, заменяется только запись в БД.
- Шаг 5 не создаёт новую запись в БД — обновляется (`db::update_game_rom`) title/rom_path у **той же** записи (тот же `id`), поэтому история `play_session`/`save_state` не теряется при смене версии.
- Шаг 6 (автозагрузка метаданных) не выполняется — версии одной игры на emu-land.net используют общую страницу/описание/обложку, повторный запрос не нужен.

## Открытые вопросы

- Нужно ли явно предупреждать в UI, если игра с таким же названием уже есть в библиотеке, прежде чем качать повторно — сейчас не уточнено, дублирование по факту решается на уровне `insert_game_if_missing` (дедуп по пути ROM, не по названию) и `unique_path` в `store_install` (дедуп по имени файла на диске).
- `.7z`-файлы (в основном GoodNES-наборы) полностью скрыты из UI, а не показаны как недоступные для установки — если понадобится их поддержать, нужна распаковка 7z на бэкенде (сейчас есть только `zip`).
