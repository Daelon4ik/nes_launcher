# Магазин игр (Store)

Позволяет искать и устанавливать ROM'ы прямо из лаунчера, без ручного скачивания файлов. Источник — тот же раздел NES/Dendy на [emu-land.net](https://www.emu-land.net/consoles/dendy/roms), что уже используется для метаданных (`src-tauri/src/metadata/scraper.rs`, `NES_SECTION_ID`).

UI-поведение описано здесь на уровне поведения; экран как таковой — см. `Store Screen` в [screens.md](screens.md).

## Как находим игру на сайте

Сайт не имеет полнотекстового поиска по разделу ROM'ов — только алфавитные списки, поэтому поиск в лаунчере реализуется через них:

1. По первой букве названия строим URL списка: `/consoles/dendy/roms/<letter>` (пример: `b` → `/consoles/dendy/roms/b`).
2. Список может быть на нескольких страницах — пагинация `/consoles/dendy/roms/<letter>/<page>`. Идём по страницам буквы, пока не найдём совпадение или не кончатся страницы.
3. В найденной строке — кнопка скачивания вида `<span class="btn-dl" onclick="mgame('/consoles/dendy/roms?act=getmfl&id=<id>', 'mfile_<id>')">`. Дальше запрашиваем этот `getmfl`-эндпоинт — он возвращает список всех доступных файлов игры, сгруппированных на сайте по разделам («Основные», «Пиратки», «Переведённые» и т.д.), каждый — ссылка вида `/consoles/dendy/roms?act=getmfl&id=<id>&fid=<fid>` с текстом-названием файла (например `BattleCity (Japan).zip`).

Точные CSS-селекторы для списка и модалки версий не зафиксированы (не проверялись вживую) — определяются при реализации, аналогично тому, как уже сделано в `metadata/scraper.rs` (`.ftext > p`, `.ss-area img`).

## UI-поведение

- **Точка входа**: кнопка «Магазин» в шапке `Main Screen` (рядом с иконкой настроек) → переход на отдельный `Store Screen`.
- **Поиск**: строка поиска сверху — пользователь вводит название, лаунчер сам определяет нужную букву/страницу (алгоритм выше) и показывает совпадения. Без введённого текста — обычный ручной просмотр списка по алфавитным вкладкам и страницам, зеркалирующий структуру сайта (на случай, если поиск ничего не находит или пользователь хочет просто полистать).
- **Выбор версии**: по клику на игру показывается **единый список всех найденных файлов** (все разделы сайта — «Основные», «Пиратки», «Переведённые» и т.д. — вперемешку), у каждой строки раздел показан как тег/подпись. Отдельного экрана выбора категории нет, автовыбора тоже — пользователь сам кликает нужный вариант.
- **Скачивание и установка**:
  1. Выбранный `.zip` скачивается по его `getmfl&fid=...`-ссылке.
  2. Архив распаковывается на бэкенде; берётся единственный/первый (по алфавиту, если их несколько) файл с расширением `.nes` внутри — остальные файлы (readme, скриншоты и т.п.) игнорируются без отдельного вопроса пользователю.
  3. Если в `Settings.rom_library_paths` настроено **больше одного** пути — перед сохранением файла на диск показывается модалка выбора, в какую из папок установить (переиспользует паттерн `InstallModal`, уже реализованный в ветке `control`). Если путь один или список пуст (используется дефолтный `<app-data>/roms`) — вопрос не задаётся, путь берётся автоматически.
  4. Установленный `.nes` регистрируется в библиотеке так же, как при ручном добавлении файла (`insert_game_if_missing`, см. `src-tauri/src/commands/library.rs`).

## Открытые вопросы

- Нужно ли явно предупреждать в UI, если игра с таким же названием уже есть в библиотеке, прежде чем качать повторно — сейчас не уточнено, дублирование по факту решается на уровне `insert_game_if_missing` (дедуп по пути ROM, не по названию).
- Реальная HTML-разметка страниц списка и модалки версий не проверялась — селекторы, скорее всего, потребуют подгонки по месту при реализации скрапера.
