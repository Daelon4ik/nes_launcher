# Экраны и UI

Подробное описание визуального стиля (цвета, типографика, компоненты) — см. [design.md](design.md).

Магазин игр (поиск и установка ROM'ов с emu-land.net) — отдельный документ, см. [store.md](store.md).

Все экраны должны полностью управляться геймпадом (D-pad/стик + кнопка подтверждения), а не только мышью/клавиатурой — см. [design.md#управление-с-геймпада](design.md#управление-с-геймпада).

## 1. Main Screen

Главный экран приложения — открывается при запуске. Реализован в Big Picture стиле (см. [design.md](design.md), раздел «Статус редизайна») — первый экран, переведённый на этот язык; остальные экраны пока на базовой раскладке.

- **Фон-герой**: во весь экран — размытая обложка игры в фокусе с градиентом-скримом (см. [design.md#компоненты](design.md#компоненты)), плавно (crossfade) меняется при переходе фокуса на другую игру. У игр без обложки — нейтральный фолбэк-градиент на палитре панелей, не сама обложка.
- **Верхняя навигация**: три раздела — Библиотека (текущий, неактивная надпись без действия) / Магазин / Настройки — иконка + подпись, активный раздел подчёркнут акцентной полосой. Справа — переключатель-кнопки «NES» / «Genesis» (фильтрует полки по `Game.platform`, см. [platforms.md](platforms.md#main-screen-фильтр-платформы)), фильтр по режиму игры (Все / Кооп / По очереди / Соло; комбинируется с фильтром платформы) и кнопка «Добавить игры» (системный диалог выбора файлов, можно выбрать несколько `.nes`/`.gen` сразу, добавляются по фактическому пути без копирования; массовое сканирование папок целиком — на вкладке «Библиотека» в `Settings Screen`).
- **Информация об игре в фокусе** (под навигацией, поверх героя): название крупно, метаинформация (режим игры, дата последнего запуска, наработанное время), три кнопки:
  - «Играть» → переход на `Emulator Screen`
  - «Кооп» → переход на `Netplay Lobby Screen` для этой игры (см. ниже, [netplay.md](netplay.md)); задизейблена для игр с `player_mode = "single"` (см. [data-model.md](data-model.md)) — им не с кем играть в кооп
  - «Удалить игру» — открывает модальное подтверждение (Отмена/Удалить, фокус по умолчанию на «Отмена», Escape = отмена); при подтверждении удаляются запись в БД (вместе с play_session/save_state), ROM-файл и обложка на диске. Пока диалог открыт, остальные элементы экрана временно `disabled`, чтобы геймпад/клавиатура не могли уйти фокусом мимо диалога
- **Полки** (горизонтальные ряды карточек, ниже героя, на сплошном фоне): «Недавно запущенные» (по `last_played_at`, не больше 15 штук) — скрыта, если ни одной игры ещё не запускали; «Все игры» — вся библиотека (в т.ч. никогда не запущенные), иначе такие игры были бы не видны нигде. Обе полки подчиняются обоим фильтрам из шапки (платформа и режим игры). Карточка игры в фокусе увеличивается — тот же фокус, что и выбор (см. [design.md#управление-с-геймпада](design.md#управление-с-геймпада)); перемещение фокуса между полками автоматически докручивает нужную карточку в видимую область.
- **Нижняя панель подсказок геймпада**: `[A] Подтвердить` / `[↑↓←→] Навигация` в обычном режиме, `[A] Удалить` / `[Esc] Отмена` — пока открыто модальное подтверждение удаления.

Действия:
- Перемещение фокуса по полке (D-pad/стрелки/мышь) сразу обновляет фон-герой и блок информации об игре — выбор и есть фокус, без отдельного шага
- Двойной клик по карточке / кнопка «Играть» / подтверждение на геймпаде (A), когда сфокусирована именно кнопка «Играть», → переход на `Emulator Screen`

## 2. Settings Screen

Экран настроек приложения. Открывается разделом «Настройки» верхней навигации `Main Screen` (см. выше), кнопка «Библиотека» в собственной шапке возвращает обратно. Переведён на Big Picture масштаб третьим после `Main Screen`/`Store` (см. [design.md](design.md), раздел «Статус редизайна») — та же шапка-навигация с иконками (Библиотека/Магазин/Настройки), что на `Main Screen`/`Store`; фон шапки — прокручивающийся размытый баннер из обложек библиотеки с затемняющим виньетированием; вкладки настроек оформлены как отдельные кнопки-плитки, а не тонкая полоса-подчёркивание. Плотный контент самих вкладок (списки, поля) — на базовой типографической шкале, см. [design.md](design.md#типографика).

Горизонтальные вкладки, реализованы все пять (см. [design.md](design.md#компоненты)):
- **Библиотека** — рабочая: список настроенных папок с ROM'ами (добавление по пути вручную, без нативного диалога выбора папки — не заведена системная зависимость под это), удаление, кнопка «Пересканировать библиотеку». Пустой список путей — используется дефолтная `<app-data>/roms`. Хранится в `Settings.rom_library_paths` (см. [data-model.md](data-model.md)).
- **Метаданные** — рабочая: список всей библиотеки со статусом («Есть описание» / «Нет описания»), у каждой игры кнопка «Обновить», сверху — «Обновить все без описания» (последовательно, не параллельно). Скрапинг реально ходит на emu-land.net (`src-tauri/src/metadata/scraper.rs`): поиск по названию игры (`/search_games?id=13&q=...`, `id=13` — раздел NES/Dendy), затем описание (`.ftext > p`) и обложка (`.ss-area img`) со страницы найденной игры. Найденная обложка скачивается на бэкенде и кэшируется локально (см. [data-model.md](data-model.md)) — сайт блокирует прямые ссылки на картинки по Referer.
- **Эмулятор**: переключатель-кнопки «NES» / «Genesis» вверху вкладки (`EmulatorTab.tsx`) — переключает, какую платформу редактируют подвкладки «Клавиатура»/«Контроллер» ниже. Громкость общая для обеих платформ, отдельно от переключателя.
  - **Громкость** — слайдер `0`–`100%`, сохраняется в `Settings.volume` по каждому изменению (см. [data-model.md](data-model.md)) и сразу применяется — множителем к сэмплам звука и в одиночной игре (`Browser`/jsnes и `GenesisCore`), и в NES-кооп-режиме (`NetplayEngine`, см. [netplay.md](netplay.md); Genesis-кооп не реализован).
  - **Настройка управления** — две подвкладки («Клавиатура» / «Контроллер»), раздельно для Игрока 1 и Игрока 2, набор действий зависит от активной платформы:
    - **NES** — Вверх/Вниз/Влево/Вправо/A/B/Select/Start (`src/utils/keyboardControls.ts`, `src/utils/jsnesGamepad.ts`).
    - **Genesis** — Вверх/Вниз/Влево/Вправо/A/B/C/Start, без Select (`src/utils/genesisControls.ts`, `src/utils/genesisGamepad.ts`) — 3-кнопочный пад, см. [platforms.md](platforms.md#контроллер-реализовано).
    - **Клавиатура** — рабочая для обеих платформ: клик по действию переводит его в режим ожидания («Нажмите...»), следующее нажатие клавиши записывается как новая привязка (для NES — `keyCode`+`code`, для Genesis — только `code`, там нет legacy-потребителей `keyCode`); сохраняется в `localStorage` (`keyboard_controls` для NES, `keyboard_controls_genesis` для Genesis — раздельные ключи, не переименование одного в другое) и сразу используется в `Emulator Screen`. Кнопка «Сбросить по умолчанию» возвращает исходную раскладку активной платформы (см. [design.md](design.md#компоненты)).
    - **Контроллер** — рабочая для обеих платформ, тем же способом, что и «Клавиатура»: клик по действию → режим ожидания («Нажмите кнопку...») → следующее НОВОЕ нажатие любой кнопки геймпада (опрос Gamepad API по кадрам, сравнение с состоянием на момент входа в режим ожидания, чтобы не среагировать на уже зажатую кнопку) записывается как физический индекс кнопки для этого действия/игрока. Слушается геймпад того слота, который редактируется (первый подключённый — Игрок 1, второй — Игрок 2; если для слота Игрока 2 отдельного геймпада ещё нет — слушается первый доступный). Хранится в `localStorage` (`gamepad_controls`/`gamepad_controls_genesis`), отдельно от раскладки клавиатуры и от раскладки другой платформы. Кнопка «Сбросить по умолчанию» возвращает раскладку Gamepad API по умолчанию для активной платформы+подвкладки (NES: D-pad 12-15, A/B 0/1, Select/Start 8/9; Genesis: D-pad 12-15, B/A/C 0/1/2, Start 9).
- **Сеть** — рабочая: имя игрока (видно партнёру при поиске/подключении к кооп-игре, `Settings.network_display_name`) и порт хоста (на нём лаунчер слушает входящее подключение в режиме хоста, `Settings.network_host_port`, см. [data-model.md](data-model.md)). Оба поля сохраняются по потере фокуса. Подробности протокола — [netplay.md](netplay.md).
- **Лаунчер**: тема (светлая/тёмная/системная, сохраняется в `Settings.theme`), внизу — версия лаунчера (нередактируемая, только для отображения).

## 3. Netplay Lobby Screen

Экран лобби P2P-кооп режима. Открывается с `Main Screen` по кнопке «Кооп» для выбранной игры, кнопка «← Библиотека» в шапке возвращает обратно. Подробное описание протокола/архитектуры — [netplay.md](netplay.md); здесь — только UI-поведение.

Два шага выбора, друг за другом (не один список из четырёх кнопок) — сначала транспорт, потом роль, т.к. «Хостить»/«Подключиться» ведут себя одинаково независимо от того, какой транспорт выбран:
1. **Транспорт**: «LAN» / «Steam» (см. [netplay.md](netplay.md) — независимые, равноправные способы подключения). «← Назад» в шапке с этого экрана ведёт в библиотеку.
2. **Роль**: «Хостить» / «Подключиться» — одинаковые кнопки для обоих транспортов, дальше экран отличается уже по содержимому. «← Назад» отсюда и с экранов хостинга/подключения ведёт на предыдущий шаг (роль → транспорт → библиотека).

- **Хостить** (LAN): читает ROM выбранной игры, считает её SHA-256, запускает TCP-приём + LAN UDP-анонс (`netplay_start_hosting`). Пока ждём — статус «Ожидание партнёра…» с подсказкой открыть тот же экран на втором устройстве. При подключении клиента (событие `netplay://client-connected`) сразу переходит на `Emulator Screen` в кооп-режиме (роль хоста, NES-контроллер 1).
- **Подключиться** (LAN): слушает LAN-анонсы (`netplay_start_discovery`), показывает список найденных хостов (имя, название игры) — список живой, хосты пропадают из него, если анонсы не приходят дольше 5 секунд. Игры, которых нет в собственной библиотеке клиента (сверка по названию), помечаются «нет в вашей библиотеке» и недоступны для подключения. При нажатии «Подключиться» на хосте: читает ROM того же локального названия, считает чек-сумму, сверяет с хостом при рукопожатии (`netplay_join_host`) — при несовпадении показывает ошибку и не переходит дальше. При успехе — переход на `Emulator Screen` в кооп-режиме (роль клиента, NES-контроллер 2).
- **Хостить** (Steam): показывает свой Steam ID (`steam_local_id`) с кнопкой «Копировать» (`navigator.clipboard`), запускает `steam_start_hosting`. Статус/переход на `Emulator Screen` — как у LAN-хостинга (то же событие `netplay://client-connected`).
- **Подключиться** (Steam): текстовое поле для Steam ID партнёра (его нужно получить от партнёра вручную — голосом, в чате) вместо списка найденных хостов — обнаружения (P2P через Steam, см. [netplay.md](netplay.md#второй-транспорт-p2p-через-steam)) нет. Кнопка «Подключиться» вызывает `steam_join`; ошибка (неверный ID, хост не запущен, чек-сумма ROM не совпала) показывается инлайново, без перехода дальше.
- Уход с экрана (в любом режиме) останавливает анонс/поиск на бэкенде (LAN) или закрывает Steam-сессию (`steam_disconnect`, безопасно вызывать и до подключения партнёра).

## 4. Emulator Screen

Экран запущенной игры (добавлен к исходным двум экранам как необходимый для функции встроенного эмулятора). Открывается с `Main Screen` по «Играть»/двойному клику/подтверждению на геймпаде, передаётся выбранная игра.

Экран выбирает движок по расширению ROM (`.gen` → Genesis, иначе NES) — без общего
интерфейса, прямым ветвлением (`isGenesis` в `EmulatorScreen`, подробности выбора движка
и почему без формальной абстракции — [platforms.md](platforms.md#движок-эмуляции)). Ниже
сначала описано NES-поведение, Genesis — отдельным блоком после кооп-режима.

Эмуляция реально работает — ядро [jsnes](https://github.com/bfirsh/jsnes) (`Browser` из пакета, см. [design.md](design.md#компоненты)):
- Байты ROM читаются бэкендом (`read_rom_bytes`, путь — от `launch_game`) и передаются в `new Browser({ container, romData })`; сам класс создаёт `<canvas>` (256×240, `image-rendering: pixelated` — принудительно через `!important` в CSS, т.к. WebKitGTK не всегда честно применяет инлайн-стиль от jsnes и без этого пиксель-арт размывается) и звук через AudioWorklet.
- **Управление**: 
  - **Клавиатура**: Игрок 1 — стрелки + X/Z (A/B), Enter (Start), Right Ctrl (Select). Для Игрока 2 добавлена раскладка WASD: W/A/S/D (перемещение), Q/E (B/A), Space (Start), Shift (Select). Переназначается на `Settings Screen` → «Эмулятор» → «Клавиатура» (см. выше).
  - **Геймпад**: jsnes сам не конфигурирует геймпады, а его встроенный конфиг геймпада привязывается по строковому id устройства — это не различает двух игроков с одинаковой моделью контроллера. Поэтому `Emulator Screen` опрашивает геймпады сам (в обход `browser.gamepad`) и применяет сохранённую раскладку напрямую через `nes.buttonDown`/`buttonUp` (`src/utils/jsnesGamepad.ts`, `getGamepadButtonMaps`). Игроки назначаются по порядку подключения: первый геймпад — Игрок 1, второй — Игрок 2. Раскладка по умолчанию — D-pad → стрелки, кнопка 0/1 → A/B, 8/9 → Select/Start; переназначается на `Settings Screen` → «Эмулятор» → «Контроллер» (см. выше), независимо для каждого игрока.
- Canvas растянут на весь экран (нет постоянной панели снизу, сжимающей область игры) — `fitScreenPixelPerfect` считает целый коэффициент масштаба от полного размера окна.
- Стрелки/клавиши этим экраном намеренно **не** перехватываются под меню-навигацию (в отличие от остальных экранов) — во время игры они должны идти в NES.
- Оверлей снизу скрыт по умолчанию и вызывается по **Tab** (клавиатура) или **LB** (геймпад, кнопка 4 — не занята jsnes) — тем же способом закрывается; пока скрыт, в углу экрана видна ненавязчивая подсказка «Tab / LB — меню». Пока открыт, Tab работает как обычная переключалка фокуса между его кнопками, а стрелки/D-pad и подтверждение (A) двигают фокус внутри оверлея через общий `useSpatialNavigation` (тот же хук, что и на остальных экранах) — он смонтирован на оверлее с самого начала (просто скрыт через `display:none`), поэтому не мешает игровому вводу, пока оверлей не открыт. «Пауза» рабочая (останавливает/возобновляет таймер кадров и звук), «Выход» — работает.
- **Save state / Load state**: рабочие, 3 фиксированных слота на игру. Кнопка открывает подменю слотов внутри того же оверлея (та же смонтированная область — `useSpatialNavigation` продолжает работать без изменений); пустые слоты в Load state задизейблены. Save записывает снимок `nes.toJSON()` (jsnes хранит полное состояние CPU/PPU/APU/mapper) как JSON-файл в `<app-data>/saves/<game_id>/slot_<n>.json` и апсертит строку в `SaveState` (уникальный индекс по `(game_id, slot)` — повторное сохранение в тот же слот перезаписывает файл и запись); Load читает файл и применяет через `nes.fromJSON()`. Esc внутри подменю слотов возвращает в главное меню оверлея, а не сразу закрывает его/выходит из игры. Недоступны в кооп-режиме (синхронизация снапшота по сети не реализована) — как и «Пауза».
- `Esc` (не занят jsnes) — закрывает оверлей, если он открыт, иначе выходит из игры. «Выход» — записывает сессию (`record_session`: длительность от открытия экрана до выхода), уничтожает инстанс эмулятора (`browser.destroy()`) и возвращает на `Main Screen`.
- Ошибка загрузки ROM (например, файл удалён с диска, или невалидный ROM — jsnes проверяет заголовок `NES\x1a`) показывается на месте экрана эмулятора вместо canvas.

**Кооп-режим** (после `Netplay Lobby Screen`, см. выше): экран получает уже прочитанный и захэшированный `romData` из лобби (повторно не читает ROM) и вместо `Browser` использует свой лок-степ движок (`src/netplay/engine.ts`, не завязан на jsnes `Browser` — подробности и почему так в [netplay.md](netplay.md)). Отличия от одиночной игры:
- «Пауза» недоступна (задизейблена) — синхронизировать паузу по сети не реализовано.
- Разрыв соединения с партнёром показывается как ошибка на месте canvas («Партнёр отключился.») — реконнекта нет, для новой попытки нужно выйти и зайти в кооп заново.
- «Выход» (или закрытие экрана любым способом) всегда разрывает сетевую сессию на бэкенде (`netplay_disconnect`).

**Genesis** (`.gen`, одиночная игра — кооп для Genesis пока explicit-ошибка, см. [platforms.md](platforms.md#netplay-кооп--спланировано-не-реализовано)): ядро [genesis_plus_gx](https://github.com/ekeeke/Genesis-Plus-GX) (WASM, пакет `romdev-core-gpgx`) поверх собственной минимальной libretro-обвязки (`src/emulator/genesis/`, подробности выбора — [platforms.md](platforms.md#движок-эмуляции)):
- `<canvas>` создаётся вручную (не библиотекой, в отличие от jsnes `Browser`) и перевешивается на каждый заход на экран; размер берётся из `GenesisCore.width/height` (обычно 320×224, может быть 256×192 в H32-режиме) — та же `fitScreenPixelPerfect`, что и у NES, но параметризованная, не на захардкоженных 256×240.
- Кадр эмулируется вручную через `requestAnimationFrame`: `core.frame()` → `core.getFrameRgba()` → `ctx.putImageData`. Звук — `AudioBufferSourceNode` с накопительным планированием времени старта (`audioCtx.currentTime`), без AudioWorklet.
- **Управление** — фиксированная раскладка, без переназначения на `Settings Screen` (Genesis-вкладка там ещё не заведена, см. [platforms.md](platforms.md#контроллер)): клавиатура Игрока 1 — стрелки, `Z`/`X`/`C` → A/B/C, `Enter` → Start; геймпад для обоих игроков — D-pad → стрелки, кнопки 0/1/2 → B/A/C, кнопка 9 → Start.
- **Save state / Load state**: те же 3 слота и тот же UI оверлея, что у NES, но кодек другой — `core.serializeState()`/`unserializeState()` (сырой `retro_serialize`-блоб ядра, ~1МБ) кодируется в base64 и идёт через ту же команду `save_state`/`load_state` (бэкенд хранит произвольную строку, ему всё равно, JSON это или base64).
- «Пауза» реализована иначе, чем у NES: RAF-цикл не останавливается, а проверяет флаг паузы на каждом тике (пропускает `core.frame()`/рендер/звук, но продолжает планировать следующий кадр) — то же видимое поведение («Пауза»/«Продолжить» в оверлее), другая реализация под капотом.
- Кооп-режим недоступен: если открыть `Emulator Screen` для `.gen`-игры с активной netplay-сессией, экран сразу показывает ошибку «Кооп для Sega Genesis игр пока не поддерживается» вместо попытки монтирования (см. [platforms.md](platforms.md#netplay-кооп--спланировано-не-реализовано)).

## 5. Store Screen

Реализовано (`src/screens/StoreScreen/`). Экран магазина игр. Открывается с `Main Screen` по кнопке «Магазин» в шапке (рядом с иконкой настроек), кнопка «← Библиотека» возвращает обратно. Подробности алгоритма поиска/установки на emu-land.net (реальные, проверенные вживую эндпоинты и селекторы) — [store.md](store.md); здесь — только UI-поведение.

**Переключатель платформы** (реализовано): две кнопки «NES» / «Genesis» над алфавитными вкладками — определяют, в каком разделе emu-land.net искать/листать (`id=13`/`/consoles/dendy/roms` или `id=39`/`/consoles/genesis/roms`, см. [platforms.md](platforms.md#store-screen-фильтр-и-источник-для-genesis)) и какое расширение ожидается внутри архива при установке (`.nes`/`.gen`). Задизейблен, пока открыта любая модалка экрана. Смена платформы, как и смена буквы, сбрасывает текущую страницу на 1.

- **Строка поиска** сверху, с дебаунсом ввода — раздел ROM'ов на сайте оказался полнотекстово ищущимся (`store_search`), так что непустой запрос сразу даёт список совпадений. Без введённого текста — вкладки по буквам (`0-9`, `A`..`Z`, `store_browse`) с пагинацией («← Назад» / «Страница N из M» / «Далее →»); смена буквы сбрасывает страницу на 1. Список в обоих режимах — карточка «Карточка игры» (обложка 3:4 + название), обложка — превью карточки с emu-land.net, подгружается лениво по карточке (см. [store.md](store.md#превью-картинки-карточек)); пока не подгрузилась/недоступна — иконка-заглушка на её месте.
- Клик по игре в списке → если название совпадает с уже установленной игрой **той же платформы** (по расширению её `rom_path`), сначала модалка «Игра уже установлена: сменить версию?» (Нет/Сменить версию), иначе сразу модалка со списком всех найденных файлов игры (`store_list_files`; все разделы сайта — «Основные», «Переведённые», «GoodNES» и т.д. — вперемешку, раздел показан подписью у строки; только `.zip`, `.7z`-наборы отфильтрованы на бэкенде); пользователь сам выбирает нужный вариант.
- Выбор файла → скачивание `.zip`, распаковка на бэкенде (`store_install`), из архива берётся единственный/первый файл с расширением активной платформы — `.nes` или `.gen` (прочие файлы игнорируются). Имя файла на диске и название в библиотеке — каноническое название игры с карточки магазина, а не имя файла из архива (там часто регион/язык/ревизия). Если в `Settings.rom_library_paths` настроено больше одного пути — модалка выбора, куда установить (пути запрошены заранее при открытии экрана); иначе путь берётся автоматически. Совпадение имени файла с уже существующим на диске решается суффиксом `(2)`, `(3)`, ... — без перезаписи. Сразу после установки бэкенд **автоматически подтягивает метаданные** (описание, обложку, режим игры) с той же страницы emu-land.net, без отдельного нажатия «Обновить» — best-effort, сбой не откатывает установку (см. [store.md](store.md)). Инлайновое сообщение об успехе на самом экране; игра появляется в библиотеке на `Main Screen` при следующем заходе туда (без принудительного перехода).
- **Смена версии уже установленной игры** (после подтверждения выше) идёт через ту же модалку выбора файла, но без запроса папки (новый файл встаёт туда же, где лежал старый) и без повторной загрузки метаданных — заменяется только сам ROM-файл, запись в библиотеке (и её история — время в игре, дата последнего запуска, save state) остаётся той же. Подробности — [store.md](store.md#установка).

## Открытые вопросы

- Переназначение кнопок геймпада (`Settings Screen` → «Эмулятор» → «Контроллер») использует индекс физической кнопки в стандартной раскладке Gamepad API; для двух геймпадов одной модели, подключённых одновременно, привязка различается только по порядку подключения (Игрок 1 = первый подключённый), а не по конкретному физическому устройству — так как Gamepad API не даёт стабильного идентификатора экземпляра устройства, только строковый `id` модели.
- Конфликты метаданных (несколько совпадений по названию ROM на emu-land.net) сейчас решаются эвристикой в скрапере — точное совпадение по названию, иначе первый результат поиска; отдельного экрана/модалки для ручного выбора нет. Может понадобиться, если эвристика будет промахиваться на реальной библиотеке.
