# Экраны и UI

Подробное описание визуального стиля (цвета, типографика, компоненты) — см. [design.md](design.md).

Все экраны должны полностью управляться геймпадом (D-pad/стик + кнопка подтверждения), а не только мышью/клавиатурой — см. [design.md#управление-с-геймпада](design.md#управление-с-геймпада).

## 1. Main Screen

Главный экран приложения — открывается при запуске.

- **Справа**: список установленных игр (библиотека). Каждый элемент — обложка + название.
- **Слева**: панель с деталями выбранной игры:
  - обложка / арт крупным планом
  - описание игры
  - дата последнего запуска
  - кнопка «Играть»
  - кнопка «Кооп» → переход на `Netplay Lobby Screen` для выбранной игры (см. ниже, [netplay.md](netplay.md)); задизейблена для игр с `player_mode = "single"` (см. [data-model.md](data-model.md)) — им не с кем играть в кооп
  - кнопка «Удалить игру» — открывает модальное подтверждение (Отмена/Удалить, фокус по умолчанию на «Отмена», Escape = отмена); при подтверждении удаляются запись в БД (вместе с play_session/save_state), ROM-файл и обложка на диске. Пока диалог открыт, остальные элементы экрана временно `disabled`, чтобы геймпад/клавиатура не могли уйти фокусом мимо диалога

Действия:
- Перемещение фокуса по списку справа (D-pad/стрелки/мышь) сразу обновляет панель слева — выбор и есть фокус, без отдельного шага
- Двойной клик / кнопка «Играть» / подтверждение на геймпаде (A) → переход на `Emulator Screen`
- Кнопка «Добавить игры» — системный диалог выбора файлов (можно выбрать несколько `.nes` сразу), выбранные ROM'ы добавляются в библиотеку по их фактическому пути (без копирования). Массовое сканирование папок целиком — на вкладке «Библиотека» в `Settings Screen`.
- Иконка-шестерёнка в шапке справа → переход на `Settings Screen`

## 2. Settings Screen

Экран настроек приложения. Открывается по иконке-шестерёнке на `Main Screen`, кнопка «← Библиотека» в шапке возвращает обратно.

Горизонтальные вкладки, реализованы все четыре (см. [design.md](design.md#компоненты)):
- **Библиотека** — рабочая: список настроенных папок с ROM'ами (добавление по пути вручную, без нативного диалога выбора папки — не заведена системная зависимость под это), удаление, кнопка «Пересканировать библиотеку». Пустой список путей — используется дефолтная `<app-data>/roms`. Хранится в `Settings.rom_library_paths` (см. [data-model.md](data-model.md)).
- **Метаданные** — рабочая: список всей библиотеки со статусом («Есть описание» / «Нет описания»), у каждой игры кнопка «Обновить», сверху — «Обновить все без описания» (последовательно, не параллельно). Скрапинг реально ходит на emu-land.net (`src-tauri/src/metadata/scraper.rs`): поиск по названию игры (`/search_games?id=13&q=...`, `id=13` — раздел NES/Dendy), затем описание (`.ftext > p`) и обложка (`.ss-area img`) со страницы найденной игры. Найденная обложка скачивается на бэкенде и кэшируется локально (см. [data-model.md](data-model.md)) — сайт блокирует прямые ссылки на картинки по Referer.
- **Эмулятор** — заглушка: пункты управления/слотов сохранений с пометкой «Скоро». Само эмулятор-ядро уже встроено и работает (см. `Emulator Screen` ниже) с дефолтными раскладками клавиатуры/геймпада — здесь имеется в виду ещё не сделанный UI переназначения кнопок и управление слотами сохранений.
- **Сеть** — рабочая: имя игрока (видно партнёру при поиске/подключении к кооп-игре, `Settings.network_display_name`) и порт хоста (на нём лаунчер слушает входящее подключение в режиме хоста, `Settings.network_host_port`, см. [data-model.md](data-model.md)). Оба поля сохраняются по потере фокуса. Подробности протокола — [netplay.md](netplay.md).
- **Лаунчер**: тема (светлая/тёмная/системная, сохраняется в `Settings.theme`), внизу — версия лаунчера (нередактируемая, только для отображения).

## 3. Netplay Lobby Screen

Экран лобби P2P-кооп режима. Открывается с `Main Screen` по кнопке «Кооп» для выбранной игры, кнопка «← Библиотека» в шапке возвращает обратно. Подробное описание протокола/архитектуры — [netplay.md](netplay.md); здесь — только UI-поведение.

- Первый экран — выбор роли: «Хостить» / «Подключиться» (кнопка «← Назад» в шапке возвращает к этому выбору).
- **Хостить**: читает ROM выбранной игры, считает её SHA-256, запускает TCP-приём + LAN UDP-анонс (`netplay_start_hosting`). Пока ждём — статус «Ожидание партнёра…» с подсказкой открыть тот же экран на втором устройстве. При подключении клиента (событие `netplay://client-connected`) сразу переходит на `Emulator Screen` в кооп-режиме (роль хоста, NES-контроллер 1).
- **Подключиться**: слушает LAN-анонсы (`netplay_start_discovery`), показывает список найденных хостов (имя, название игры) — список живой, хосты пропадают из него, если анонсы не приходят дольше 5 секунд. Игры, которых нет в собственной библиотеке клиента (сверка по названию), помечаются «нет в вашей библиотеке» и недоступны для подключения. При нажатии «Подключиться» на хосте: читает ROM того же локального названия, считает чек-сумму, сверяет с хостом при рукопожатии (`netplay_join_host`) — при несовпадении показывает ошибку и не переходит дальше. При успехе — переход на `Emulator Screen` в кооп-режиме (роль клиента, NES-контроллер 2).
- Уход с экрана (в любом режиме) останавливает анонс/поиск на бэкенде.

## 4. Emulator Screen

Экран запущенной игры (добавлен к исходным двум экранам как необходимый для функции встроенного эмулятора). Открывается с `Main Screen` по «Играть»/двойному клику/подтверждению на геймпаде, передаётся выбранная игра.

Эмуляция реально работает — ядро [jsnes](https://github.com/bfirsh/jsnes) (`Browser` из пакета, см. [design.md](design.md#компоненты)):
- Байты ROM читаются бэкендом (`read_rom_bytes`, путь — от `launch_game`) и передаются в `new Browser({ container, romData })`; сам класс создаёт `<canvas>` (256×240, `image-rendering: pixelated` — принудительно через `!important` в CSS, т.к. WebKitGTK не всегда честно применяет инлайн-стиль от jsnes и без этого пиксель-арт размывается) и звук через AudioWorklet.
- **Управление**: клавиатура работает из коробки (стрелки + X/Z — A/B, Enter — Start, Right Ctrl — Select для игрока 1; у jsnes есть и раскладка для игрока 2 на нумпаде). Геймпад jsnes сам не конфигурирует (ждёт мастер настройки нажатием кнопок) — вместо этого при подключении геймпада на экране сразу применяется дефолтный маппинг под стандартный Gamepad API layout (`src/utils/jsnesGamepad.ts`): D-pad → стрелки, кнопка 0/1 → A/B, 8/9 → Select/Start.
- Canvas растянут на весь экран (нет постоянной панели снизу, сжимающей область игры) — `fitScreenPixelPerfect` считает целый коэффициент масштаба от полного размера окна.
- Стрелки/клавиши этим экраном намеренно **не** перехватываются под меню-навигацию (в отличие от остальных экранов) — во время игры они должны идти в NES.
- Оверлей снизу скрыт по умолчанию и вызывается по **Tab** (клавиатура) или **LB** (геймпад, кнопка 4 — не занята jsnes) — тем же способом закрывается; пока скрыт, в углу экрана видна ненавязчивая подсказка «Tab / LB — меню». Пока открыт, Tab работает как обычная переключалка фокуса между его кнопками, а стрелки/D-pad и подтверждение (A) двигают фокус внутри оверлея через общий `useSpatialNavigation` (тот же хук, что и на остальных экранах) — он смонтирован на оверлее с самого начала (просто скрыт через `display:none`), поэтому не мешает игровому вводу, пока оверлей не открыт. «Пауза» рабочая (останавливает/возобновляет таймер кадров и звук), save/load state — неактивны (жду отдельной задачи под слоты сохранений, jsnes умеет `toJSON`/`fromJSON`), «Выход» — работает.
- `Esc` (не занят jsnes) — закрывает оверлей, если он открыт, иначе выходит из игры. «Выход» — записывает сессию (`record_session`: длительность от открытия экрана до выхода), уничтожает инстанс эмулятора (`browser.destroy()`) и возвращает на `Main Screen`.
- Ошибка загрузки ROM (например, файл удалён с диска, или невалидный ROM — jsnes проверяет заголовок `NES\x1a`) показывается на месте экрана эмулятора вместо canvas.

**Кооп-режим** (после `Netplay Lobby Screen`, см. выше): экран получает уже прочитанный и захэшированный `romData` из лобби (повторно не читает ROM) и вместо `Browser` использует свой лок-степ движок (`src/netplay/engine.ts`, не завязан на jsnes `Browser` — подробности и почему так в [netplay.md](netplay.md)). Отличия от одиночной игры:
- «Пауза» недоступна (задизейблена) — синхронизировать паузу по сети не реализовано.
- Разрыв соединения с партнёром показывается как ошибка на месте canvas («Партнёр отключился.») — реконнекта нет, для новой попытки нужно выйти и зайти в кооп заново.
- «Выход» (или закрытие экрана любым способом) всегда разрывает сетевую сессию на бэкенде (`netplay_disconnect`).

## Открытые вопросы

- Конфликты метаданных (несколько совпадений по названию ROM на emu-land.net) сейчас решаются эвристикой в скрапере — точное совпадение по названию, иначе первый результат поиска; отдельного экрана/модалки для ручного выбора нет. Может понадобиться, если эвристика будет промахиваться на реальной библиотеке.
- Нужна ли поддержка нескольких профилей пользователей?
