# Экраны и UI

Подробное описание визуального стиля (цвета, типографика, компоненты) — см. [design.md](design.md).

Все экраны должны полностью управляться геймпадом (D-pad/стик + кнопка подтверждения), а не только мышью/клавиатурой — см. [design.md#управление-с-геймпада](design.md#управление-с-геймпада).

## 1. Main Screen

Главный экран приложения — открывается при запуске.

- **Справа**: список установленных игр (библиотека). Каждый элемент — обложка + название.
- **Слева**: панель с деталями выбранной игры:
  - обложка / арт крупным планом
  - описание игры
  - дата последнего запуска
  - кнопка «Играть»

Действия:
- Перемещение фокуса по списку справа (D-pad/стрелки/мышь) сразу обновляет панель слева — выбор и есть фокус, без отдельного шага
- Двойной клик / кнопка «Играть» / подтверждение на геймпаде (A) → переход на `Emulator Screen`
- Кнопка «Добавить игры» — системный диалог выбора файлов (можно выбрать несколько `.nes` сразу), выбранные ROM'ы добавляются в библиотеку по их фактическому пути (без копирования). Массовое сканирование папок целиком — на вкладке «Библиотека» в `Settings Screen`.
- Иконка-шестерёнка в шапке справа → переход на `Settings Screen`

## 2. Settings Screen

Экран настроек приложения. Открывается по иконке-шестерёнке на `Main Screen`, кнопка «← Библиотека» в шапке возвращает обратно.

Горизонтальные вкладки, реализованы все четыре (см. [design.md](design.md#компоненты)):
- **Библиотека** — рабочая: список настроенных папок с ROM'ами (добавление по пути вручную, без нативного диалога выбора папки — не заведена системная зависимость под это), удаление, кнопка «Пересканировать библиотеку». Пустой список путей — используется дефолтная `<app-data>/roms`. Хранится в `Settings.rom_library_paths` (см. [data-model.md](data-model.md)).
- **Метаданные** — рабочая: список всей библиотеки со статусом («Есть описание» / «Нет описания»), у каждой игры кнопка «Обновить», сверху — «Обновить все без описания» (последовательно, не параллельно). Скрапинг реально ходит на emu-land.net (`src-tauri/src/metadata/scraper.rs`): поиск по названию игры (`/search_games?id=13&q=...`, `id=13` — раздел NES/Dendy), затем описание (`.ftext > p`) и обложка (`.ss-area img`) со страницы найденной игры. Найденная обложка скачивается на бэкенде и кэшируется локально (см. [data-model.md](data-model.md)) — сайт блокирует прямые ссылки на картинки по Referer.
- **Эмулятор** — заглушка: пункты управления/слотов сохранений с пометкой «Скоро» — эмулятор-ядро ещё не встроено.
- **Лаунчер**: тема (светлая/тёмная/системная, сохраняется в `Settings.theme`), внизу — версия лаунчера (нередактируемая, только для отображения).

## 3. Emulator Screen

Экран запущенной игры (добавлен к исходным двум экранам как необходимый для функции встроенного эмулятора). Открывается с `Main Screen` по «Играть»/двойному клику/подтверждению на геймпаде, передаётся выбранная игра.

Реализован каркас, без самого эмулятор-ядра (см. [design.md](design.md#компоненты)):
- Область на месте эмулятора — заглушка: название игры, путь к ROM (получен через `launch_game`), пометка «Эмулятор ещё не встроен». Ошибка загрузки (например, файл ROM удалён с диска) показывается тут же.
- Оверлей снизу, всегда видимый (без hover-появления/автоскрытия — упрощение для каркаса, см. открытые вопросы): пауза / save state / load state — неактивны, ждут эмулятор-ядра; кнопка «Выход» работает.
- «Выход» — записывает сессию (`record_session`: длительность от открытия экрана до выхода) и возвращает на `Main Screen`.

## Открытые вопросы

- Конфликты метаданных (несколько совпадений по названию ROM на emu-land.net) сейчас решаются эвристикой в скрапере — точное совпадение по названию, иначе первый результат поиска; отдельного экрана/модалки для ручного выбора нет. Может понадобиться, если эвристика будет промахиваться на реальной библиотеке.
- Нужна ли поддержка нескольких профилей пользователей?
- Оверлей `Emulator Screen` сейчас всегда виден снизу; стоит ли делать hover/хоткей-появление с автоскрытием, как задумано в design.md, когда дойдём до реального эмулятор-ядра?
