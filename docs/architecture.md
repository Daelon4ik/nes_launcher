# Архитектура

## Общая схема

```
┌─────────────────────────────┐        ┌───────────────────────────┐
│   Frontend (React + TS)      │  IPC   │   Backend (Rust / Tauri)   │
│   webview                    │ <────> │                             │
│                               │        │  commands/  db/  metadata/ │
└─────────────────────────────┘        └──────────────┬──────────────┘
                                                        │
                                          ┌─────────────┴─────────────┐
                                          │                            │
                                   ┌──────▼──────┐           ┌─────────▼────────┐
                                   │  SQLite DB   │           │ Файловая система  │
                                   │ (библиотека, │           │ (ROM'ы, обложки,  │
                                   │ сохранения)  │           │  save states)      │
                                   └─────────────┘           └───────────────────┘
```

## Backend (`src-tauri`)

Rust-часть отвечает за всё, что требует доступа к системе: файлы, сеть, БД. Frontend не имеет прямого доступа к диску — только через IPC-команды.

- **`commands/library.rs`** — сканирование папки с ROM'ами, добавление/удаление игр из библиотеки
- **`commands/emulator.rs`** — запуск/пауза/сброс эмулятора, управление save state (создание/загрузка слотов)
- **`commands/saves.rs`** — история запусков, время в игре, статистика прогресса
- **`db/`** — слой доступа к SQLite (модели, миграции, запросы)
- **`metadata/scraper.rs`** — скачивание метаданных и обложек игр по названию ROM с внешнего источника (например, TheGamesDB / libretro thumbnails)

## Frontend (`src`)

- **`screens/`** — три основных экрана: `MainScreen`, `SettingsScreen`, `EmulatorScreen` (см. [screens.md](screens.md))
- **`api/`** — тонкий слой обёрток над `@tauri-apps/api` `invoke(...)`, типизированный под конкретные команды backend'а
- **`store/`** — глобальное состояние приложения (текущая игра, список библиотеки, настройки)
- **`components/`** — переиспользуемые UI-элементы (карточка игры, список, модалки)
- **`hooks/`** — логика, переиспользуемая между экранами (например, `useGameLibrary`, `useEmulator`)

## Поток данных: запуск игры

1. Пользователь кликает на игру на `MainScreen`
2. Frontend вызывает команду `emulator::launch(rom_path)`
3. Backend отдаёт путь к ROM и метаданные обратно во frontend
4. `EmulatorScreen` монтирует эмулятор в webview и загружает ROM
5. При выходе из игры frontend вызывает `saves::record_session(...)`, backend пишет длительность сессии и обновляет дату последнего запуска в БД

## Почему Tauri, а не Electron

- Меньший размер бинарника и потребление памяти (нет встроенного Chromium + Node, используется системный webview)
- Rust-backend удобен для безопасной работы с файловой системой и потенциально — для нативного эмулятора NES в будущем (вместо JS-эмулятора)
